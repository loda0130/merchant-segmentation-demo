# 商家圈组 · 产品需求文档
版本：0.1.0（开发基线）｜日期：2026-11-27｜状态：已确认需求 + 明示的 Demo 假设
仓库：loda0130/merchant-segmentation-demo

## 1. 目标与范围
运营人员依据店铺特征配置圈组规则，周期扫描全量店铺，按配置自动新增/剔除；未自动执行的差异由运营处理。保留候选批量处理及可追溯历史。
本期交付静态可交互 Demo，使用原生 HTML/CSS/JavaScript、虚构样本，不接生产接口，不执行真实定时任务、打标、公告、罚款或资金操作。

## 2. 需求依据与修订优先级
- U（用户已明确）：按条件自动圈店。创建和编辑时统一维护圈选条件，每条依次选择组间关系、条件类型和条件值。新增类型为店铺标签、店铺类型（集运/自发货/海外仓）、主营大类和店铺 ID。已有的是否自营条件兼容回显和维护。
- U：自动新增和自动剔除固定开启；全量扫描间隔下拉仅支持 1 小时；列表提供「手动更新」，立即扫描当前圈组。
- U：店铺 ID 通过规则维护，人工处理通过候选页签完成；人工决定受保护，扫描仅提醒。
- 历史方案曾通过入组/移组打标签；最新方向改为条件圈店，本期不执行入组打标及移组删标。标签 ID 是条件输入，不能混为输出标签。
- D（本稿为可开发 Demo 补充）：下述字段长度、排序、表达式结合顺序、金额单位、停用/删除边界等。不得宣称这些已由用户逐项确认。上线前需业务确认第 10 节。
- 本项目不承接海外仓价卡、权益包、供应链金融还款组的业务逻辑。

## 3. 页面与操作
### P01 圈组列表
顶部面包屑“商家管理 / 商家圈组”，标题及“创建圈组”主按钮。
筛选：圈组名称/ID、状态、自动新增、自动剔除、圈选条件。圈选条件使用两级下拉，一级为条件维度，二级为具体条件，全局只选一个二级条件。查询时按圈组已配置的规则值与其他筛选项组合匹配。
Demo 假设（D）：店铺标签和店铺 ID 筛选按规则中配置的完整 ID 匹配。默认按更新时间倒序，分页 10/20/50 条（默认 20）。
表格：
|列|展示/交互|
|---|---|
|圈组信息|组名可打开详情；ID 次行；备注两行截断，详情可看全文|
|圈选条件|完整条件摘要最多三行，查看详情获得完整带括号表达式|
|店铺数|当前成员数，点击进入成员视图|
|自动维护|新增开启、剔除开启；启用时显示每 1 小时|
|待处理|可加入 x / 待剔除 y；手动保护 z（为前两类的子集，不相加）|
|状态|启用/停用，文字与颜色同时展示|
|维护信息|创建人+创建时间、更新人+更新时间分行，每个时间不拆分|
|操作|手动更新、编辑、修改历史、店铺进出历史、停用/启用、删除|
手动更新仅在启用时可用，运行期间同一圈组不可重复触发，完成后刷新当前行并显示加入与剔除数。
无记录/无匹配均保留表头。行操作可分两行，但不能压缩成难以点击的密集文字。

### P02 创建/编辑圈组
分区顺序：基本信息 → 圈选条件 → 自动维护。
基本信息：圈组名称必填、备注选填。
圈选条件：使用同一列表添加或移除条件，每条依次选择「且」「或」「且非」、条件类型和条件值。店铺标签和店铺 ID 均可输入一个或多个数字 ID，以空白或逗号分隔，自动去重并保留前导零。店铺类型及主营大类支持多选。表达式实时预览。
已有规则回显时保留原有标签组关系，原独立维度以「且」接在标签组之后。原规则中的是否自营作为已有条件显示，仍可修改或移除。
自动新增和自动剔除默认勾选并置灰，无法取消。全量扫描间隔使用下拉，仅有「1 小时」且默认选中。
提交前展示条件、开关及预计变化摘要；创建/编辑保存规则本身不暗中修改成员（D），等待下一轮扫描。
至少配置一个实际限制条件（D），避免空规则误圈全量。每条条件须填全或移除。非法 ID、空名称阻止保存。取消/Esc 不改变已保存规则及成员。
编辑成功增加规则版本号，写入修改历史；旧候选标记“待重新扫描”，不能按旧规则批量执行（D）。

### P03 圈组详情
顶部显示组名、状态、条件摘要、两个自动开关、扫描间隔、最近扫描时间/结果、规则版本。
置顶差异提醒：“可加入 x”“待剔除 y”，提示“其中 z 条受手动保护，仅提醒”。无差异显示无需处理；扫描失败显示最后成功结果时间，不能用失败结果清空成员。
标签页：组内店铺、可加入、待剔除。手动删除的组外店铺仍可出现在“可加入”中并标明手动保护。
各页字段：选择框、店铺名称/ID、类型、标签、累计充值金额（示例币种）、主营大类、是否自营、匹配结果/原因、来源及时间、手动保护说明。
支持按店铺 ID/名称搜索，来源过滤（D），本页全选、已选数量、批量加入/剔除。切换页签/筛选清除选择（D），批量只处理明确勾选的对象。
批量确认显示圈组名、动作、有效数量、受保护数量及“这是人工操作，会更新手动决定”。确认时重验规则版本、当前匹配与成员状态；过期对象跳过并给出原因。
仅未入组且满足当前规则的对象可以在候选视图批量加入；仅已入组且不匹配的对象可批量剔除。

### P05 修改历史 / 店铺进出历史
修改历史：时间、操作人、动作、规则版本、变更前/后；包括创建、编辑、启停、删除，不把扫描无变化当作配置修改。
进出历史：时间、店铺名/ID、加入/剔除、来源（系统扫描/人工批量处理，历史样本保留原有来源）、操作人、原因、规则版本、扫描/批次 ID。
系统操作人明确为“系统”。发生实际成员变更才记进出历史；重复扫描无差异不重复记成员变更。
可按日期/操作类型/来源/店铺 ID 过滤（D）。长规则通过展开查看完整前后值；无结果显示空态。
停用/删除需二次确认。停用保留规则、成员与历史，停止扫描与自动变更（D）；允许查看，恢复启用后下一轮扫描生效，不补跑所有错过的周期（D）。
删除采用 Demo 软删除（D），从正常列表移除、停止扫描并保留审计；未模拟下游关联，真实删除联动由业务确认。

## 4. 条件语义
设 G 为单条条件的匹配结果。一条店铺标签、店铺类型、主营大类或店铺 ID条件中的多值按「或」匹配。
D：不同类型的条件也按列表顺序从上到下左结合计算，界面显示括号。首条选择「且」或「或」时令 E1=G1，选择「且非」时令 E1=NOT G1。
后续条件按连接词计算 Ei=Ei-1 AND Gi / Ei-1 OR Gi / Ei-1 AND NOT Gi。例如 ((标签条件 或 类型条件) 且非 主营大类条件)。
店铺标签与店铺 ID 使用完整字符串匹配，保留前导零。尚未出现在店铺快照里的 ID 可以配置，扫描时仅匹配快照中的店铺。未知或缺失的业务属性不能使对应条件通过，包括选择「且非」时。其他条件仍按连接词参与计算；整体未匹配时显示缺失原因（D）。

## 5. 扫描与人工决定
先用同一份全量虚构店铺快照和规则版本计算 match，再决定动作。每次扫描留扫描 ID、快照时间、版本和摘要；并发扫描禁用重复触发（D）。
Demo 的列表「手动更新」和详情「模拟扫描」执行同一套扫描规则。1 小时为配置值，Demo 仅在用户触发时执行扫描。

|成员状态|匹配|保护|自动开关|结果|
|---|---|---|---|---|
|组外|是|NONE|自动新增开|加入，系统历史|
|组外|是|NONE|自动新增关|可加入提醒|
|组外|是|FORCE_OUT|任意|仅可加入提醒，标手动删除保护|
|组内|否|NONE|自动剔除开|剔除，系统历史|
|组内|否|NONE|自动剔除关|待剔除提醒|
|组内|否|FORCE_IN|任意|仅待剔除提醒，标手动新增保护|
|组内|是|任意|任意|保持|
|组外|否|任意|任意|保持|

保护以 groupId + shopId 为键，独立于成员集合；最后一次成功人工变更决定 FORCE_IN/FORCE_OUT，规则编辑、启停、自动开关切换不清除（D）。
无效/重复/跳过项不更新人工决定（D）。本期不提供“清除保护”入口，解除方式及期限在真实上线前确认。
产品界面固定双开，决策表中的关闭分支用于兼容旧策略和模型回归。自动处理后仅剩未执行差异进入提醒；不要把已自动执行的数量继续列为待处理。
扫描失败不变更成员，不删除历史，保留最后成功快照。重复扫描必须幂等；批量结果按实际变更数计算。

## 6. 数据字典（D 为技术建议）
|对象|字段|约束|
|---|---|---|
|Group|id,name,note,status|ID 不变；name 1–50 字、去首尾空白、同名阻止；note ≤200 字；enabled/disabled/deleted|
|Rule|conditions|有序条件数组。每项含类型、连接词和该类型的值；保留对旧规则字段的读取兼容|
|Policy|autoAdd,autoRemove,intervalHours,ruleVersion|当前配置的两个开关固定为 true，间隔为 1 小时；版本单调递增|
|Shop|id,name,tags,types,totalRechargeMinor,currency,categoryId,isSelfOperated|全为虚构；types 数组可表达多种经营类型（D）|
|Membership|groupId,shopId,joinedAt,source|同组同店最多一条|
|Override|groupId,shopId,decision,operator,at|NONE/FORCE_IN/FORCE_OUT，独立保存|
|Scan|id,groupId,ruleVersion,at,status,summary|success/failed，失败保留上次成功数据|
|ConfigLog|id,groupId,action,before,after,operator,at|深拷贝快照，不随编辑改变旧历史|
|MemberLog|id,groupId,shopId,action,source,operator,reason,ruleVersion,batchId,at|只记录实际进出；时间含秒|
|Candidate|groupId,shopId,action,reasons,protected,ruleVersion,scanId|可重新计算，执行前重验|

## 7. 虚构验收样本
所有名称、店铺 ID、标签 ID、人员、金额、时间为虚构示例，不使用历史截图上的真实信息。
统一样本规则：标签 101；类型含海外仓；主营大类不限；非自营。
|店铺ID|标签/类型/金额/自营|初始成员|保护|双开扫描预期|
|---|---|---|---|---|
|900001|101 / 海外仓 / 1500 / 否|否|NONE|系统加入|
|900002|102 / 海外仓 / 1500 / 否|是|NONE|系统剔除|
|900003|102 / 集运 / 200 / 否|是|FORCE_IN|保留，待剔除提醒|
|900004|101 / 海外仓 / 1500 / 否|否|FORCE_OUT|不加入，可加入提醒|
|900005|101 / 海外仓 / 2000 / 否|是|NONE|保持|
|900006|102 / 自发货 / 300 / 是|否|NONE|保持|
双开扫描后成员 3 家（900001、900003、900005），可加入 1、待剔除 1、手动保护冲突 2，新增成员历史恰好 2 条。
连续第二次扫描不得产生新的成员历史；不得把 900004 的人工保护因其不在组内而丢失。

## 8. 验收标准
- AC01 创建/编辑包含所有条件，自动新增和自动剔除均勾选并禁用，扫描间隔仅有 1 小时；取消后值不变；非法输入保留草稿并指向错误。
- AC02 四种条件在同一列表维护，跨类型 OR/AND/AND NOT 与括号预览一致；完整 ID 匹配；空规则或缺值条件拒绝保存；原规则回显后沿用原本的匹配结果。
- AC03 列表手动更新与详情模拟扫描均符合第 7 节的双开结果；停用不可手动更新，规则修改后必须重新扫描。
- AC04 手动增删跨重复扫描、规则修改、启停后仍受保护；只提醒不反向执行。
- AC05 店铺 ID 条件支持多值去重与完整 ID 匹配；保存时成员保持不变，下次扫描按规则维护。
- AC06 详情顶部提醒、候选筛选、本页全选、批量确认和数量一致；过期候选不能直接执行。
- AC07 系统/人工日志可区分，旧规则快照不可变，成员日志只记录实际变化。
- AC08 停用停止自动维护，删除二次确认；取消/Esc 不改变状态。
- AC09 1920×1080、1440×900、1280×800 页面无意外横向溢出；横滚仅在表格；按钮可点击，弹窗底部可达。
- AC10 Pages 根入口、组件页、参考图及相对资源正确，无外部 CDN/真实接口；无控制台错误。
- AC11 扫描失败不损坏成员；重复点击不会重复提交；空态、无匹配、无效 ID均有反馈。

## 10. 上线前待确认，不阻塞静态 Demo
1. 组间“非”的准确业务语义、混合且/或优先级；本稿用显式左结合 AND NOT。
2. 店铺类型是否多身份；本稿采用类型数组。
3. 生产周期的实际范围与平台时区。本期配置为 1 小时，Asia/Shanghai 展示。
4. 手动保护期限及解除入口；本稿永久保留到下一次相反人工变更。
5. 停用时是否允许手动维护、删除对下游影响；本稿停用仅允许查看/恢复/删除，成员维护按钮禁用。
6. 是否另需入组打标；当前最新需求不包含，禁止自行接入旧打标方案。
